# Communications hub — decision support, re-entry focus, enforced TTL (2026-10-07)

Operator spec 2026-10-07: Communications is a decision-support system, not a message log. Every item carries
a category, a priority, a confidence score, a TTL with an expiry timestamp, a status and an actionability flag.
Nothing relevant sits outside the feed. Stale items leave every view on their own, then are archived and removed.

Decisions: approvals, protection incidents and broker facts follow the **same TTLs** as everything else; removal
is **archive, then delete**.

## TTLs

| Category | TTL |
|---|---|
| System Alert, Operational Issue | 72 h |
| Re-Entry, Risk, Reward, High Conviction Opportunity, Threat, Market Event, News, Security Alert | 96 h |
| Watchlist Candidate, Operator Conversation | 168 h (1 week) |

"Unless reaffirmed by new data": a newer item on the same symbol (or the same headline topic) in the same
category supersedes the older one, so the live item always carries a fresh clock. Approval requests are never
superseded by topic.

## Update 2026-10-20 — delivery health and un-owned reservations

| Piece | PR / status | What it does |
|---|---|---|
| Delivery summary API | #1866 N3, LIVE in `f6f56e365` | `GET /api/v2/communications/deliveries/summary` (`communications_portal.delivery_summary`) runs one aggregate over the **whole** `communication_deliveries` table. It returns `unsettled` (RESERVED, SENDING), `failed` (FAILED, BOUNCED, EXPIRED), `total`, `oldest_unsettled_at` and `oldest_unsettled_age_s`. When the DB cannot be read it returns `status: UNAVAILABLE` with null counts, never 0. |
| Delivery-health strip | #1866 N3, LIVE | `CommunicationsHub.tsx` + `lib/commsDeliveryHealth.ts` read that summary rather than counting the latest 500 rows client-side, and show UNAVAILABLE or STALE instead of 0. |
| Provider message id | #1866 N2, LIVE | `telegram_alert.record_operator_message(..., provider_message_id=)`: callers that sent through their own transport (`autonomy_watchdog/telegram_system`) pass the id they received. Only `send_telegram`'s own path reads the ambient `last_message_ids()`. An explicit `None` means "no id". OUTBOUND returns `{ok, errors, status, settled, provider_message_id}`. |
| Reserve only when someone owns the delivery | #1885, MERGED-NOT-SERVED | `CommunicationEvent.channels` still defaults to `["telegram"]`, but as `AssumedChannels` (`event.channels_were_assumed()`). `client.should_reserve_delivery()` reserves a ChannelDelivery only for an **OUTBOUND** event that **named** its channel. An INBOUND event or an assumed channel still writes the ledger, outbox and subject-memory rows, but no reservation. |
| Stale-reservation reaper | #1885, MERGED-NOT-SERVED, **opt-in** | `delivery.reap_stale_reservations(max_age_s=3600, apply=False, limit=500)` never sends and never invents a provider id: INBOUND → CANCELLED, unclaimed outbound → EXPIRED, stale SENDING → UNKNOWN. The floor is 600 s, so it cannot race a send. Run it with `comms_lifecycle.py --steps reservations` (dry run) and add `--apply` to settle. It is **not** in the hourly cron's default steps until the `comms-lifecycle` cron-inventory row is approved (operator freeze 2026-10-09). |
