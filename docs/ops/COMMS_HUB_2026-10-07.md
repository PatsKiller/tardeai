# Communications hub — decision support, re-entry focus, enforced TTL (2026-10-07)

Operator spec 2026-10-07: Communications is a decision-support system, not a message log. Every item carries
a category, a priority, a confidence score, a TTL with an expiry timestamp, a status and an actionability flag.
Nothing relevant sits outside the feed. Stale items leave every view on their own, then are archived and removed.

Decisions: approvals, protection incidents and broker facts follow the **same TTLs** as everything else; removal
is **archive, then delete**.

## TTLs

| Category | TTL |
|---|---|
| System Alert, Operational Issue | 72 h |
| Re-Entry, Risk, Reward, High Conviction Opportunity, Threat, Market Event, News, Security Alert | 96 h |
| Watchlist Candidate, Operator Conversation | 168 h (1 week) |

"Unless reaffirmed by new data": a newer item on the same symbol (or the same headline topic) in the same
category supersedes the older one, so the live item always carries a fresh clock. Approval requests are never
superseded by topic.

## Update 2026-10-21 — the second ledger: telegram_outbox, and why reports_archive "failed"

The 2026-10-21 audit found the strip saying `failed 0` while Coordination → Events outbox listed about 149 telegram_outbox
"failed" sends a day, all on channel `reports_archive` with reason `ok=false`. **Those rows were not failed sends.**
`report_capture.archive_message(suppressed=True)` stores `ok = not suppressed`, so every message the router **held** —
P3 intents archived for the digest (`intent_p3_digest`), P2 intents held in quiet hours (`intent_p2_quiet_hours`) and
legacy router suppressions (`telegram_alert.py` `_intent_send` and `_legacy_send`) — is written with `ok=false`. The
reports archive is a DB-only ledger; nothing was attempted to Telegram, so no chat id or config is involved.
`notification_outbox_projection.TG_STATE` then mapped every `ok IS FALSE` to `failed`. It was a labelling bug.

| Piece | PR / status | What it does |
|---|---|---|
| Archive holds are `held` | this PR, MERGED-NOT-SERVED | `notification_outbox_projection`: a `reports_archive` row with `ok=false` is state `held` (reason "held for digest (archived, not sent by design)"). Any other `ok=false` row is still `failed`. `held` is a known state for the silent-senders anomaly. |
| Telegram failures on the strip | this PR, MERGED-NOT-SERVED | `delivery_summary()` adds `telegram_outbox_failed_24h`, `telegram_outbox_failed_24h_by_channel`, `telegram_outbox_held_24h` and `telegram_outbox_sent_24h` from `telegram_outbox`, a separate ledger from `communication_deliveries`, so it is never added to `failed`. If the table can't be read, the fields are null and `telegram_outbox_error` is set. The main summary still answers. The strip shows "Telegram sends failed 24h N (by channel)" and "held for digest N (archived, not failures)". |
