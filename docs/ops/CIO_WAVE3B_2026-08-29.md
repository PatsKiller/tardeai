# CIO Wave 3B — council, notification policy, checkpoint binding (2026-08-29)

Builds the machinery that *decides* whether to notify. **Notify is not
enabled.** Every decision records `would_send: false`, delivery is the existing
shadow adapter, and a PR-wide grep confirms zero Telegram call sites added.

## The four pins, and how each is held

| pin | how it is enforced |
|---|---|
| `CIO_SITUATION_NOTIFY` stays 0/unset | policy reads the env, never assigns it — a test asserts no `os.environ[...] =`, `setenv` or `putenv` in the module |
| `CIO_TELEGRAM_INTERDICT` stays on | never read for control flow, never cleared; delivery refuses any adapter whose `is_live` is true |
| MBI ceiling 0 | a test asserts the string `MBI` and `memory_behavior_influence` appear in **none** of the three new modules |
| ROTATE advisory-only | a test asserts `ROTATE` appears in none of them |

Plus: no new producer (grep for `send_cio_message`, `api.telegram.org`,
`RealTelegramAdapter`, `cio_telegram_transport` across the PR — clean), the
council calls no model, and `SpecialistArtifact` performs no HTTP.

## 1. `SpecialistArtifact@v1-lite`

`scripts/lib/cio_specialist_artifact.py` — schema, validator, jsonl writer at
`data/cio/cio_specialist_artifacts.jsonl`. Writer is used by tests and the
deterministic join only.

Two deliberate strictnesses: an unknown `provider` **raises** rather than
coercing (a provider silently normalised to `stub` would make a paid call look
free in the cost ledger), and a `stub` artifact costing anything but 0.0 is
rejected.

Distinct from the pre-existing `cio_specialist_artifacts.py` (plural), which
extracts advisory positions from agent handoffs. Not a replacement.

## 2. `CIOCouncilSynthesis@v1`

`scripts/lib/cio_council_synthesis.py` — joins VALID artifacts + CASE_SUMMARY +
desk pin + thesis fields into a T/D/A block the operator product already
renders.

States: `AGREED` · `SINGLE_SOURCE` · `DISPUTED` · `NO_VALID_ARTIFACTS`.

**Disagreement is labelled, never resolved.** Two VALID artifacts with opposite
positions produce `DISPUTED` with both shown. No winner is picked, because
picking one is exactly the judgement that would need a model — and a
deterministic tie-break would be a *fake* one: the alphabetically-first provider
is not more correct.

A stance is read only from explicit `position`/`stance`/`verdict` fields. It is
never inferred from prose; parsing a sentence for a stance is the same silent
judgement in a cheaper disguise. `model_called`, `mints_plan` and
`attaches_plan` are all `False` and asserted.

## 3. `NotificationPolicy@v1`

`scripts/lib/cio_notification_policy.py` → `IMMEDIATE | DIGEST |
COMMAND_CENTER_ONLY | SUPPRESSED`, persisted with `notification_id`, decision
and reason.

| case | decision |
|---|---|
| duplicate subject | `SUPPRESSED` (checked first — 36 open S5 plans are one question) |
| not material | `SUPPRESSED` |
| S5 cash deployment | `SUPPRESSED` |
| S1 observational | `SUPPRESSED` |
| S6 fire | `COMMAND_CENTER_ONLY` — never `IMMEDIATE` |
| council `DISPUTED` | `COMMAND_CENTER_ONLY` |
| otherwise material | `DIGEST` |

`IMMEDIATE` is reachable by the schema but nothing returns it without an
explicit operator-directed flag, and even then delivery stays the shadow
adapter. `SUPPRESSED` never reaches an adapter at all.

The defaults are quiet on purpose: the failure mode of a notification system
isn't silence, it's noise that trains the operator to ignore it.

## 4. OutcomeCheckpoint plan binding

Checkpoints key on `decision_id`; completed research keys on `plan_id`. That
mismatch is *why* complete→checkpoint is UNCOMPUTABLE rather than 0%.

New writes must now **declare** `plan_id` — but a null value is allowed when
`plan_binding` says why. Requiring a non-empty value outright rejected
legitimate cash- and dust-bound checkpoints, which have no plan by nature, and
those are the very rows the operator said not to rewrite. Declared-null keeps
them writable while excluding them from the rate's denominator, so the ratio
becomes computable over bound rows instead of silently unknown.

**History untouched:** the 148 CASH-bound and 50 dust-bound rows are unchanged.

## 5. Eligible-jobs surface

`schedule_surface` now carries `skip_reason` per row and a `skipped_sample`
block, both capped at 10. Ops only — a test asserts the block is never routed
to Telegram.

## 6. EDGAR

Registry row only: official SEC URL, `refresh: event`,
`dimension_scope: entity`, grade **C**. No crawler, no full-text sweep.

It is the first *entity*-scoped row in the registry, which is exactly why it
cannot `corpus_hit` — entity dimensions are never corpus-closed, and grade C
would block it regardless. Registering it records the intent without granting
the authority.
