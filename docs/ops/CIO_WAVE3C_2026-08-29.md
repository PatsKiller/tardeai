## 1. `DeliveryReceipt@v1`

`scripts/lib/cio_delivery_receipt.py` — records a `NotificationPolicy@v1`
decision and the channel it *would* have used, deduped by `dedupe_key`.

| decision | would_channel |
|---|---|
| `IMMEDIATE` | `telegram` |
| `DIGEST` | `digest` |
| `COMMAND_CENTER_ONLY` | `cc` |
| `SUPPRESSED` | `none` |

`SUPPRESSED` maps to **`none`**, not to a channel that merely stayed quiet — a
suppressed decision has no destination at all. `would_send` is a literal
`False` in the builder, never derived from state that could flip it, and a
receipt carrying `would_send: True` is refused by `validate` before it can be
written.

A receipt for a message never sent sounds odd until you need it: it makes "the
system stayed quiet" auditable rather than merely believed.

## 2. Lesson / hypothesis bind

`scripts/lib/cio_lesson_bind.py` — after a checkpoint whose `plan_binding` is
`bound`, mint `lesson_id` + a hypothesis flagged `REVIEW_READY`.

Three limits, each tested:

- **Unbound checkpoints mint nothing.** A cash- or dust-bound checkpoint has no
  plan, so a lesson from it would have no subject. Recorded as skipped with a
  reason — the skip record is persisted too, because "we looked and there was
  nothing to bind" is evidence, and dropping it silently is how a coverage
  number becomes unverifiable.
- **Support only.** `support_only: True`, `requires_human_review: True`, and
  `AGENT_COMMITMENT` / `COMMITTED` / `ACTIONABLE` are rejected by `validate`.
- **MBI stays 0.**

## 3. `CanonicalStoreRegistry@v1` spine

Extended, **not duplicated** — that module already *is* the spine, and a second
index of the same ids is the drift bug this session has fixed twice (two
`total_cash` writers, two freshness laws).

Registered: `cio.specialist_artifacts`, `cio.notification_policy`,
`cio.delivery_receipts`, `cio.lesson_binds` — each with `id_fields`, plus a
declared `CANONICAL_ID_FIELDS` namespace and `stores_minting(field)`.

**The spine immediately earned its keep:** `stores_minting("lesson_id")`
returned `NONE`, which caught that lesson binds were being minted with nowhere
registered to keep them. The store was added rather than the check softened.

## 4. Graph impact, 1-hop, held non-dust only

`scripts/lib/cio_graph_impact_held.py` wraps the existing
`cio_graph_impact` (already `HOP=1`, cap 5) with the eligibility rule and
records **why** a subject was skipped: `cash_or_non_entity`, `dust_residual`,
`not_a_ticker`, `test_symbol`, `not_held`.

An empty neighbour list and "not eligible" must not look identical — skipped
subjects carry `graph_impact: None` and a reason. `mints_watch_identity: False`.

One bug found here: the first cut required `classify_instrument_id` to return
`"ticker"`, which it never emits — it *names* the types it recognises (CUSIP,
ISIN) and returns `UNKNOWN_INSTRUMENT_ID` for everything else, so every real
ticker was being skipped as `not_a_ticker`. Now it excludes the recognised
non-ticker types instead of demanding a positive verdict that does not exist.

## 5. EDGAR — one filing, not a crawler

`MAX_FETCHES = 1`, enforced by a counter; `fetch=False` by default.

**SCHD resolves `UNAVAILABLE`, exactly as the brief anticipated.** It is an ETF
and has no CIK in SEC's `company_tickers` map. Guessing an issuer — the
sponsor? the largest constituent? — would attach a fabricated identity to a
real filing, so it is not guessed.

The proof used Visa, the largest held operating company:

dimensions are never corpus-closed and grade C could not close a gap anyway.
