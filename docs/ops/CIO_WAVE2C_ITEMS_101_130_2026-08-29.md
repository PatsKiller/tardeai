## The finding: S1 had the same disease as S6

The S6 dust rule shipped hours earlier. Auditing item 115 turned up **35 open S1
plans on dust** — JEPI 20, SRNE 14, LDOS 1 — accumulating by the identical
mechanism, through a different branch:

| evaluator | branch | formula |
|---|---|---|
| S6 | `disposition_loss_100.0pct_hold_36.0m` | `(basis − last) / basis` |
| S1 | `deep_drawdown_from_basis_100.0pct` | `(basis − last) / basis` ≥ 25% |

A residual is permanently ~100% below its cost basis, so **both** fire on every
pass forever. Fixing S6 alone would have left the larger of the two leaks open.

`_s6_subject_skip_reason` is now `_subject_skip_reason`, shared by both
evaluators — one rule, not two copies that drift.

## Harness trap worth knowing

Re-running `collect_surface_a_status()` locally reported **AXTI and FATN as
`UNAVAILABLE`** — which would have read as a regression against the operator's
`EXITED` baseline. It was not. `collect_previously_traded()` takes no `root`; it
queries **Postgres** through `api_v2._db_query` and returns `[]` on failure, so
an ad-hoc shell without DB env drops both names through the `previously_traded`
branch.

The live payload is correct: **SCHG / AXTI / FATN EXITED, FANG UNAVAILABLE.**
`TRADEAI_ROOT` fixes the file-backed collectors; it does nothing for the
DB-backed ones. Check a status claim against `/api/v3/cio/home` before believing
a local recomputation.
