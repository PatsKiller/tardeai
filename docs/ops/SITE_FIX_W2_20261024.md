# W2: payload budgets, paging and lazy reads

Status: local source; browser proof blocked. Owner: W2, with the handoffs below.
Design-Task: DSN-20261024-site-load-P1-T1. Base: origin/main d635873e1, after #2072.

Large polls previously repeated observation history and uncapped list rows. W2 adds
server windows with full-population counts, keeps history behind a paged detail
read, and admits page requests only while their tab or shared visible strip needs
them. These are read adapters over existing owner stores; no new authoritative
store, provider, broker, job trigger, scheduler change or execution rule is added.

## Contracts

- List windows accept `offset` and `limit` (default 50, maximum 100).
  `pagination` contains `offset`, `limit`, `returned`, `total`, `has_more` and
  `next_offset`. Advance using `next_offset`: the byte budget can end a page before
  its requested limit. The pager remembers actual boundaries for Previous.
- Ordinary list envelopes stay below 500,000 bytes; Candidates envelopes below
  200,000 bytes. Budgets account for the server's ASCII escaping and JSON spaces.
  A single oversized row or oversized metadata is an explicit gap, never a
  fabricated replacement or an unbounded response.
- Candidates default to the Actionable filter. `filter=ALL|ACTIONABLE|CURRENT|CONFLICT`
  applies before paging. Counts describe the full owner union. Unknown remains
  null. Lists carry the latest source observation and the original observation
  count; `view=summary` carries global counts without rows.
- `candidate_id` plus `history_source=TRADE_AI|ACTIVE_TRADER` pages that source's
  observations using the same window. No history is silently discarded.
- Prospects takes `lane`; only that lane's rows are transferred, while all lane
  counts/caps/overflow remain. `lane_membership` includes every curated/overflow
  name, so an alert on another page never becomes a false orphan. `conflict_count` counts engine-flagged names on the returned page; a missing engine check remains null. Existing lane caps remain visible.
- Curation supports `view=mine|suggests|both`; each section has its own page metadata.
  The My List `mine` kind filter runs before paging; `kind_counts` covers the full
  filtered population. Mine is never dropped by signal expiry. Suggests excludes
  expired/invalidated stages and expired/malformed expiry timestamps **before**
  ranking. Its copy names the ranked research universe and the capped Prospects
  view, rather than promising identical membership.
- W1 `cio_truth.stance_for` supplies stance/conviction by confirmed GUID, using one
  batch projection. Lower opinions stay in explicit conflicts/source evidence.
  Missing canonical values are gaps. W1 `stop_for` alone classifies cached stop
  states; W2 supplies stored observations and never reads a broker.
- Watchpool SELECT paging follows a stable `(entered_at,id)` order over its
  deduplicated population. Status/origin totals are separate full-population
  aggregates. Directive count, proposed count, desk-staged count and retained-hit
  count come from SQL aggregates, not the 40-row child feeds or the page length.
- Hermes findings/backlog use SQL count + LIMIT/OFFSET. Findings use `EXISTS` for
  embeddings so multiple embeddings cannot duplicate a finding. Audit rows also
  have a bounded window and separate total. W6 owns their UI controls.

## Proof and unresolved dependencies

The copied-state verifier names only five JSON/journal inputs, hashes them, copies
them to a fresh scratch directory, then runs the real candidate reader against
that copy. It checks reachability, byte budgets, 180 polls/12 clients, source/copy
immutability and isolated handler RSS. It never opens the production DB/network.
It does **not** prove full served-server RSS with every browser page open.

The first copied-state receipt observed 37 candidates across two pages, maximum
189,640 bytes including envelope, and peak isolated handler RSS 114,122,752 bytes.
A later fresh receipt at `~/.cache/rtc/w2-real-copy-20261025-final/receipt.json`
reached the same 37 candidates and 189,640-byte maximum with 113,979,392 bytes peak
isolated handler RSS, 180 polls and 12 clients. An existing exact-query broker
snapshot was labelled stale; refresh started no work. Inputs and copies were
unchanged. A final-source replay against a fresh copy of those already captured
inputs is at `~/.cache/rtc/w2-real-copy-final-source-0038/receipt.json`: same 37
candidates/189,640-byte maximum, 113,922,048 bytes peak isolated handler RSS,
stale broker snapshot and zero refresh work. Source/copies remained unchanged.
This validates the final cache-shape guard without any new live read; it is not
served-server RSS proof.

calls the old autocal, reprice, engine or broker helpers to fill that gap.
