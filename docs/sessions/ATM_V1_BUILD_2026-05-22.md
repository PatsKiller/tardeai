## approve_proposal Abstraction Note

The current canonical approval entry point is `approve_proposal()` in
`paper_trade_logger.py`. This function:
- Fetches the proposal
- Runs market revalidation (gets live price from Alpaca)
- Creates a paper_trade record
- Returns success/failure

Then `submit_paper()` in `proposal_paper_submitter.py`:
- Runs 10 safety gates
- Submits bracket order to Alpaca paper via `alpaca_paper_adapter.py`

**Today:** The submit path is Alpaca-specific. Before any non-Alpaca account is
ATM-enabled, the submission step needs to be abstracted to:
1. Read `target_account` → look up `routing_adapter` from accounts table
2. Dynamically import and call the adapter's submit function
3. Each adapter implements the same interface: `submit(conn, proposal_id) -> dict`

This is a Phase 2 item (post-v1). For now, all ATM-enabled accounts must route
through the Alpaca paper adapter, which is the only one that exists.
