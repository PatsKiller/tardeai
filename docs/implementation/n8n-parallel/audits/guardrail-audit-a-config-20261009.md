# Guardrail Audit A — Config/Data guardrails vs the n8n path

_Read-only audit, 2026-10-09. Source: `origin/main` @ `a9fa8b89b` (worktree `/home/johnclaw/tradeai-wt-guardA-20261009`). Host facts (crontab, rendered env) were read for **names only**; no secret value was printed or stored. Nothing was changed or pushed._

## Top findings

1. **The run boundary works as designed.** `config/n8n_run_allowlist.json` is read by the relay, the gateway and the executor. The LLM boundary also works: the bridge loads the process registry, routing policy, model registry, caps and reservation for `n8n_model_job` exactly as for every other caller. Fourteen lanes are runnable. None of them sends, touches a broker, or calls `gate_and_generate`.
2. **The executor gives every lane the full rendered secret env (high).** The unit loads `%t/tradeai/env`, which holds 126 variables. The variable names include the gateway HMAC keys, the relay bearer, `N8N_ENCRYPTION_KEY_ESCROW` and 27 broker or Telegram names. The executor passes all of it to every lane child (`n8n_run_executor.py:337`, `:216`). `secret_registry.yaml` has no field that says which consumer may use which secret. The executor's own header says it "holds no HMAC key".
3. **The never-list is prose backed by a merge-time test (high).** No runtime code re-checks forbidden tokens, and the executor accepts `--allowlist` and `--code-root` overrides.
4. **What runs inside the n8n instance is ungoverned (high).** The node-type allowlist only covers the generated workflow templates. The Telegram and provider chokepoint ratchets only scan repo Python, so an `httpRequest` or `code` node can reach any host.
5. **n8n has no identity or authority row (high).** It is missing from `agent_registry.json`, `agent_clients.yaml`, `agent_maturity_catalog.json` and `platform_silos.json`. The gateway's route denylist is separate from `agent_runtime_mvl.json` `global_denied_tools`; nothing keeps the two in step.
6. **Cost and scheduling controls are thin on the bridge path (med).** Off-peak deferral, `routing.cost_ceiling_usd` and `latency_budget_ms`, and the registry's `tools_allowed` and `advisory_only` flags are not enforced there. Cron-header env flags such as `LLM_DEFER_OFFPEAK` are not set in the executor unit. `expected_services.json` does not declare the gateway or the bridge unit.

## How to read this

**n8n path audited:** n8n workflow → `scripts/n8n_run_relay.py` (bearer, allowlist, live-lane env) → `scripts/lib/n8n_coordination_gateway.py` (HMAC claim, scopes, route denylist, run allowlist) → ledger `runs` → `scripts/n8n_run_executor.py` (allowlist re-read, lane lock, timeout, optional `market_day_gate.sh`, runs the lane's own argv) ; LLM: gateway `model_job` → `scripts/lib/n8n_model_job.py` (template, schema, artifact store allowlist) → `scripts/lib/cio_governed_model_bridge.py` (process registry, routing policy, legacy model reject, caps, reservation, Ring 2).

**n8n status values**

| Value | Meaning |
|---|---|
| **YES** | Enforced on the n8n path today: the same loader runs inside the relay, gateway, executor, bridge, or an allowlisted lane script, or the control is trigger-agnostic on the host. |
| **YES†** | The rule is loaded inside a specific script, so it would still apply if that script ran under the executor. No allowlisted lane reaches it today: the lane is on the never-list or not yet migrated. Parity is inherent. |
| **YES‡** | Merge-time CI, ratchet or measurement gate over repo code. It does not depend on what triggers the work and does not inspect n8n-instance content. |
| **PARTIAL** | Applies in part. The reason column says which part is missing. |
| **NO** | Not enforced on the n8n path. The rule is bypassed, or the file has no loader at all. |

**Kind:** technical = code reads it and refuses or limits something; procedural = CI, ratchet, registry or review discipline; policy = operator intent such as risk limits, authority or notification policy.

Loader cells cite `file:line` from `grep` on origin/main (the first non-archive hits; `(+N)` means more tests exist). A cell marked NOT VERIFIED could not be confirmed.
