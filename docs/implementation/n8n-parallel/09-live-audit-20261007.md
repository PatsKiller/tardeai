## Executive summary

n8n **is installed** on this host as a Docker Compose lab (`n8nio/n8n:2.43.0`, loopback port 5678, own Postgres 16). It is **not production-ready** and it does **not** have hosted-n8n parity: it runs in regular (non-queue) mode with no Redis, no container healthcheck, no scheduled backup, no monitoring unit installed, a single owner account with MFA off, and the Community edition cannot use external secrets, projects/RBAC, environments, SSO, Git version control, log streaming or multi-main. It holds **zero** credentials and four workflows (two 5-minute HTTP monitors, two inactive bench workflows). It owns no production fact and no production effect.

The production automation estate it would coordinate is large and already governed elsewhere: **483 live crontab lines, 92 user timers, 144 user services (27 running), 2 system timers, 13 OpenClaw jobs**, 174 declared lanes in `config/lane_registry.json` (137 ACTIVE), 46 cron lines plus 4 timers plus 4 services that touch brokers or positions, and a DeepSeek-only paid LLM path with 1,378 governed calls and $1.21 of spend in the last 24 hours behind a loopback bridge with reservations and caps.

**Recommendation:** keep n8n as an observer and coordinator behind the already-built, already-served coordination gateway (HMAC claims, forbidden routes, SQLite ledger, projection route). Do not move any owned fact, send, broker call, or paid LLM call into it. Harden the lab to a supportable baseline (healthcheck, watchdog unit, nightly dump, MFA, PG17), then run the five shadow pilots for four weeks and decide the one credential question (ADR) on evidence. Bitwarden Secrets Manager stays the master secret store; n8n Community cannot talk to it natively and does not need to.
