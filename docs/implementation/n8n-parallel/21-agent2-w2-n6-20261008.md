## Policy and dependency findings

1. AGENTS 23.3 explicitly forbids a DOF SQL path in the run allowlist. Both
   observed runners write SQL; the pipeline also includes model-based scoring.
   The handoff's permission to repeat existing cron writes does not resolve that
   policy conflict. The supervisor/operator must resolve it explicitly. A
   projection-only `dof_reader` role is not executor write authority.
2. The executor currently runs commands from the Trade AI code root using its
   own interpreter. A foreign-project cwd/interpreter contract is not supported.
   Proposed commands record the actual DOF argv but are NOT placed in `lanes`.
   No broad subprocess escape, shell wrapper or new environment authority is
   introduced to route around this boundary.
3. Four enabled OpenClaw jobs were inspected by ID. No corresponding
   `~/.openclaw/cron/runs/<job-id>.jsonl` receipts exist. The two monthly jobs
   report last-run OK but delivery not requested; this is not proof of sending.
   No message payload, credential value or personal record is copied.
4. `PROPOSED` from the packet is not a supported LaneRegistry state. The four
   uninstalled n8n replacements use NEVER_SCHEDULED, ESTABLISHED provenance,
   and explicit NO_SIGNAL. This does not claim the enabled legacy OpenClaw job
   is unscheduled or deactivate it.
5. Generator IDs differ from canonical N6 IDs. Rows link the generated workflow
   IDs as proposed replacement identities; current generator payloads still use
   aliases. Agent 3 owns the generator work, so no competing generator edit or
   fabricated replacement file is made. Alignment is required before import.
6. The generated last-day reminder uses day 28 instead of legacy `L`; those
   calendars are not equivalent. The two generated one-shot reminders use
   annual cron and require a bounded single-fire/deactivation guard. All remain
   blocked, not silently accepted as faithful schedules.
