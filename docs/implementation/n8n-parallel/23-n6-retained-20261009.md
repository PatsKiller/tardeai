migration board and the lane registry.
as_of: 2026-10-09.
Authority: metadata, board rendering and tests only. Nothing is executed, installed, enabled,

## Decision

Tranche N6 ("other projects", six lanes) is closed by policy. Its lanes stay on the scheduler that
fires them today and are not migrated to n8n. The n8n scheduler-of-record program target becomes
**65 lanes in scope, 6 retained** (the tranche list still names all 71).

Cause: AGENTS.md §23.3 — the run allowlist may never contain a sender (Telegram or email), and the
run route must never open a DOF SQL path. Every N6 lane is one or the other, so no N6 lane can ever
become an allowlisted `coordination/run` lane. Doc 21 (Agent 2 W2) recorded the same blockers as
"not waived"; this decision closes them instead of leaving them pending.

| Lane | Retained on | Why it cannot move |
|---|---|---|
| `dof-run-pipeline` | cron (`0 20 * * 6`) | DOF SQL writer (six stages) |
| `dof-rescan-tickets` | cron (`0 18 * * *`) | DOF SQL writer (`UPDATE dof_ticket_lookups`) |
| `openclaw-reminder-claude-plan-1` | OpenClaw job `676c2212` (`0 9 24 * *`) | Telegram sender |
| `openclaw-reminder-claude-plan-2` | OpenClaw job `0775cd6b` (`0 9 L * *`) | Telegram sender; also no 5-field equivalent for `L` |
| `openclaw-reminder-supergrok-expiry` | OpenClaw at-job `9a26d34d` (2026-10-20T14:00Z) | Telegram sender, one-shot |
| `openclaw-reminder-sentinelone-earnings` | OpenClaw at-job `a9c337e0` (2026-12-07T13:00Z) | Telegram sender, one-shot |

The four OpenClaw jobs were read (read-only) from the OpenClaw cron `jobs.json` on 2026-10-09: all
four `enabled: true`; the two monthly jobs show `lastRunStatus: ok`.

## What changed

- `config/n8n_migration_tranches.json`: N6 gains `status: RETAINED_BY_POLICY`, `decided`, `reason`;
  every N6 lane gains `retained_on` and `retained_reason`. Top level gains `in_scope_lane_count: 65`
  and `retained_lane_count: 6`. The lane list is unchanged.
- `scripts/n8n_migration_board.py`: new phase `RETAINED` for lanes of a retained tranche (never
  `NOT_STARTED`); the board reports `in_scope_lane_count` / `retained_lane_count`; `per_tranche`
  carries the tranche `status`. A retained lane whose registry row says kind `n8n` is flagged
  `RETAINED_LANE_ON_N8N` (a contradiction, never shown as CUT_OVER).
- `config/lane_registry.json` (edited through `_cutover._serialise_registry`, byte-exact round trip):
  - the two DOF rows: `note` only (appended "N6 retained on cron by operator decision 2026-10-09
    (AGENTS.md §23.3)"). They were already kind `cron` ACTIVE.
  - the four reminder rows were kind `n8n` / `NEVER_SCHEDULED` describing the never-imported n8n
    replacement. The registry has no OpenClaw scheduler kind and no other OpenClaw-scheduled row, so
    they now use kind `event` — the registry's kind for a lane no host cron/systemd entry fires — with
    `expression: openclaw-cron:<job id>`, `emitted_by: openclaw-scheduler`, `match: <job id>` and
    `cadence` = the OpenClaw schedule. `state` → `ACTIVE`, `state_since` → 2026-10-09, `state_reason`
    rewritten, `note` appended. Output signal stays `none`, so the lane monitor says UNVERIFIABLE
    (never ORPHANED, never a false LIVE).
- The generated N6 workflows under `workflows/generated/pending/` are kept, not deleted, never
  imported. `n8n_workflow_templates.py --check` is unchanged and clean.
- The run allowlist is unchanged; a new test asserts no lane of a retained tranche is ever in
  `config/n8n_run_allowlist.json` `lanes`.

## Reopening

Reopening N6 needs an AGENTS.md §23.3 amendment (operator-approved) first; then remove `status`
from the tranche and re-register the reminder rows through a registry PR.
