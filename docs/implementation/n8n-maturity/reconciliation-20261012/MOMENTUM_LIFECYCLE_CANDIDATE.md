# Momentum lifecycle implementation and activation packet

Status: DRAFT_FOR_OPERATOR_REVIEW
as_of: 2026-10-12
Evidence: SOURCE_ONLY; operative admission and runtime acceptance remain unproven
Consumer: migration integrator and operator review

This package integrates a host momentum lifecycle monitor and gateway/relay/alerting adapters, with an inactive n8n observer candidate. It is source preparation. The package does not activate scheduling, pause legacy triggers, review a contract, arm remediation, read a credential or call a model.

The user requested six-AM ET scanning, complete momentum lifecycle monitoring, governed LLM diagnosis and bounded self-healing, and shared Active Trader/Trade-AI advisory data. The six-AM requirement is a trading-day output expectation. The existing five-minute scalp live schedule retains its RTH market gate. A completed run with zero GO or proposals can be healthy.

## Source implementation

- `scripts/lib/n8n_momentum_lifecycle.py`: pure calendar/receipt/output evaluator, fixed-path read-only host collector, admission checks, stable incident findings, and deterministic bounded recovery planner.
- `scripts/n8n_momentum_lifecycle.py`: explicit fixture or host-metadata evaluation. `--write-monitor` writes only `data/runtime/momentum_lifecycle_last.json`; it requires host collection, the real clock, the code-root candidate policy, enabled configuration and operative monitor admission. Explicit snapshots cannot become runtime receipts. The durable reader checks the policy digest and host collection identity as well as deployed SHA and age. `--dry-run` never writes or submits a run. A completed evaluation exits zero even when watched data has P1 findings, so failure reporting does not stop monitor scheduling; `--exit-code` is an explicit operator health-check option. Calculation/IO exceptions still fail.
- `config/n8n_momentum_lifecycle_candidate.json`: disabled, disarmed, unreviewed candidate. Schedules come from the operative lane registry rather than duplicated forecast schedules.
- `workflows/tradeai-momentum-lifecycle-candidate.json`: inactive read-only stage-aware observer; schedule -> authenticated lifecycle readback. An admitted live receipt is validated; HTTP403 typed boundaries with actual server stage shadow lead to the existing dry-run last-run metadata read. The existing generic `tradeai-dispatcher` is the sole run requester; this workflow has no `/due` or `/run` branch. Errors use the existing `tradeai-incident-router`. Successful execution data is not retained. It holds only the existing relay credential reference and performs no external send, shell, model or secret action.
- `MOMENTUM_GATEWAY_INTEGRATION.patch`: the original five-file integration proposal retained as historical evidence. Its gateway library, HTTP gateway, relay, fan-in and host notifier changes are now integrated in the source tree; do not reapply the old patch to that tree. Integrated regression tests exercise the actual adapters.

The gateway addition is `coordination/status`, operation `momentum_lifecycle`, with existing HMAC `coordination_read` authentication. It rejects every extra request field, including caller paths, snapshots, enabled flags, review flags and recovery choices. The relay exposes authenticated `GET /momentum-lifecycle` with no query parameters. It uses the existing gateway transport and read claim. The provider uses the served code root and state root derived from existing gateway configuration; it requires actual operative monitor admission with content-bound owner review and rejects a missing, stale or wrong-SHA monitor receipt. Reading never writes or requests recovery.

The fan-in reads bounded monitor findings using the existing `scalp_lane`/SIEM mapping. The integrated host notifier adapter independently reads the same canonical source/item keys when n8n or the fan-in is unavailable. It cannot double an incident represented by both paths. Ordinary P1 failures retain P1 delivery and the incident dedupe window; severity alone never invents an operator decision. Explicit credential or storage-reclamation operator tasks retain dedupe off. Transport delivery, escalation and recovery still need an authorized host failure-to-notification proof.

## Host metadata contract

The collector reads only:

| --- | --- |

| `data/runtime/momentum_lifecycle_inputs.json` | Unaccepted declarations only. Supplied counts/SHA are retained with path/hash provenance, but supplied basis/business/credential status cannot establish proof or credential health. An accepted producer binding remains absent. |
| `data/runtime/trade_ai_cache.json` and bounded source scan packages | Existing public metadata with nested business run/date, separate populations and per-field path/schema/hash provenance. Missing producer SHA is not borrowed from CURRENT or wrapper time. Availability is not accepted output proof. |
| Registry-declared `data/runtime/*_last.json` receipts | Bounded nonsecret existing lane receipt fields. Paths outside the fixed public runtime shape are refused; missing accepted writer/output binding remains NOT_MEASURED. |
| `data/runtime/scalp_cycle_monitor_last.json` | Existing `ScalpCycleMonitor@v1` projection. Missing SLO values remain null; source-specific RTH missed-slot rules are reused. |
| `data/runtime/n8n_failure_diagnosis_last.json` | Existing diagnoser's bounded liveness/count status only. No model answer, evidence pack or action text is forwarded. |
| `/tmp` and state filesystem metadata | Free bytes/inodes. Zero capacity is FAILED; positive capacity alone does not establish a reviewed operating reserve. No file deletion or lock clearing is offered. |

When stronger host input metadata is absent, the collector also projects the actual canonical cache and bounded Active Trader journal through the existing shared-candidate reader. It keeps nested canonical run/date identity, actual producer SHA (including missing identity), and separate summary/union counts. Availability is not accepted business proof: basis and business verdict remain `NOT_MEASURED`, and no consumer acknowledgements are invented.

Each business product must carry `available`, `run_id`, `run_date`, actual producer `source_sha`, aware `finished_at`, `basis=REAL_BUSINESS_OUTPUT`, `business_status=ok`, and explicit nonnegative population counts. A served cache must also carry `derived_from_run_id` matching the real scan package. `HEALTH_AUTOHEAL` timestamps do not prove business work. The producer source SHA is not inferred from a cache mtime or the monitor's own served SHA.

Under `population_contract=scan_partition`, `classified_total + manual_total == scanned_total`. Overlay universe/GO counts have separate populations. This accepts a 67-row scan partition of 44 classified and 23 manual rows without forcing the separate Active Trader universe to equal 67. Notification metadata must bind body, link and footer subjects consistently; incidents contain a finite reason code rather than those subjects.

Under `population_contract=shared_signal_union`, the product also requires `projection_hash`, `source_verdicts_preserved=true`, and `consumer_views.active_trader` / `consumer_views.trade_ai`, each with the same projection hash, run ID and business date. A newly authored shared API is not proof that both consumers read it. Pending Active Trader advisories remain pending; source verdicts, conflicts and timestamps remain visible. The monitor does not create GO, approve proposals, change watch subscriptions or duplicate the independent Active Trader alert path.

A `d:` coordination slot proves the requested slot, not that the n8n trigger was natural. Natural closure requires explicit `trigger_kind=NATURAL_SCHEDULE`, complete requested/started/finished chain, and matching receipt run/lane/slot/SHA/exit. Manual canaries, lock skips and unknown trigger provenance cannot close that requirement. Two completed run IDs in one slot require duplicate-effect inspection. Existing legacy work may have outputs while lacking n8n requests; `expected_fire_without_request` identifies the n8n ownership/evidence gap and does not assert that legacy business work never ran.

## Governed diagnosis and recovery

Existing `scripts/n8n_failure_diagnosis.py` already implements grounded, scrubbed host evidence -> governed process `n8n_lane_failure_diagnosis` / template `lane_failure_diagnosis.v1` -> strict bounded catalogue action -> deterministic handler -> `host_run_request` -> durable diagnosis/action receipts. The SIEM bridge folds diagnosis into the rows it owns, and the fan-in exposes low confidence/refusal/failure escalation. This implementation is reused rather than selecting a model or provider in n8n.

At this source base, `config/n8n_remediation_catalogue.json` is labelled **PROPOSED — operator review before activation**. Its implementation and action rows do not establish review authority. Lifecycle coverage records this boundary. `trade-ai-scalp-live` remains explicitly excluded from external LLM diagnosis by the existing catalogue library and is escalated. Financial proposal/promoter paths, senders, secret render, cookies, daemons, deletion, policy edits and arbitrary model-generated commands are never candidate recovery actions.

The source planner's only candidate recovery ID is `momentum-cache-reconcile`. A concrete helper now exists in `scripts/momentum_cache_reconcile.py`, but operative admission remains absent. It uses the existing bounded shared projection reader and writes only its own resettable `SharedMomentumCandidates@v1` derivative cache and `MomentumCacheReconcile@v1` receipt. Unchanged source snapshots do not rewrite that derivative. Original Trade-AI cache and Active Trader journal bytes, source verdicts, unknown producer SHA and stale dates are preserved. This rebuild cannot heal canonical scanner/cache drift or establish consumer acceptance. The planner still requires the actual registry ACTIVE/cutover stage, reviewed target contract with reviewer, decision reference and operative body digest; actual deployed SHA is checked independently, allowlist/live/flock admission, proven output dependencies, reviewed storage reserve, and original durable budget-slot history. It uses existing `class_verdict`/`next_attempt_at` policy, backoff, catch-up window and attempt caps. Polling cannot reset a slot or create fresh retry budgets. The existing dispatcher submits `d:<lane>:<mode>:<original-slot>:aN` keys from `coordination/due`; the gateway persists the original slot, attempt and parent and the executor retains final admission. `host_run_request` explicitly refuses server slot keys. Manual `rem-*` IDs would omit this accounting, so this monitor no longer emits them or creates a second retry authority. The existing governed LLM diagnoser retains its separately capped catalogue action path; the lifecycle CLI itself does not submit requests.

FINVIZ_COOKIE remains in Bitwarden Secrets Manager. Its existing Command Center System > secrets host render/validator flow is an operator task. The existing credential-health API performs a live probe and is not called by this monitor. n8n reads only completed authorized nonsecret health metadata. It receives no item value, item ID, cookie file, provider credential or secret-render capability.

`MOMENTUM_HEALTH_CONTRACT_PROPOSALS.json` contains 15 fully authored external DRAFT contracts, including the monitor, resettable derived-cache helper and read-only observer. Each defines purpose, declared owner and confirmation boundary, connections, healthy/degraded/failed criteria, provisional baseline/calendar/population rules, alerting, remediation, evidence and review date **2026-10-13**. Existing operative contract identity/review provenance is recorded and preserved. Missing acceptance remains `NOT_MEASURED`; no UNKNOWN placeholder passes as approval. At this source base, the catalogue has no operative `trade-ai-scalp-live` health contract; its proposal therefore requires an explicit review rather than assuming one exists.

Review binds `contract_body_sha256` to canonical JSON of the operative contract excluding `review` and `status`. Its actual `reviewed_by`, auditable `decision_ref` and explicit `ownership_confirmation=OWNER_ACCEPTED` are required; missing, empty or arbitrary ownership values refuse admission even with a matching digest. Proposed body digests are authored, but reviewer decisions are null and every contract stays DRAFT. This uses existing operative configuration and introduces no new review store or authority. SOURCE_COMMIT and run/output receipt SHA independently prove runtime identity; a final release SHA is never embedded into its own committed contract.

The shared adapters, bounded public metadata reader and lifecycle/cache/CLI/shared-evidence tests are integrated and registered in the native gate catalogue. An accepted business-output producer binding and the full final-head profile remain required. Guardrail parity for monitor/helper/observer is authored in `docs/implementation/n8n-parallel/parity/momentum-lifecycle-candidate-20261012.md`, with current enforcement, source/kind, candidate enforcement, isolated validation and explicit runtime collection actions.

The observer checks a real dry-run requested/started/finished chain before live monitor admission. Its compact last-run API does not expose full receipt SHA or effect counters; those, natural trigger provenance and zero business effects remain `NOT_MEASURED` with an explicit exact-host collection action. This is not shadow acceptance or a fabricated live health receipt. Unexpected live refusals, missing/stale admitted receipts and P1 findings remain errors.

The named derivative-cache helper permits an explicitly admitted first live canary at operative stage `canary`, or a later `cutover` run, with its existing enabled/armed, ACTIVE, safe-class, OWNER_ACCEPTED, content-bound review and live/flock checks. Its receipt records the actual stage and retains `business_acceptance=NOT_MEASURED`; stage alone does not prove manual or natural provenance. Autonomous recovery remains cutover-only with original durable budget-slot, dependency, storage and retry-policy proofs. The separate scalp fallback-retirement gate requires three clean n8n market days; that wait is not a prerequisite for executing the helper's first authorized canary.

The staging hold is `dispatch.mode=off`: current `compute_due` ignores row state, so PAUSED or a disabled candidate flag alone cannot stop an allowlisted dry-run dispatch. The packet carries a separate reviewed ACTIVE + dry_run shadow transition; do not apply it during staging. The isolated negative regression runs the actual due calculator against both allowlisted staged rows and confirms zero emitted items.

Activation requires actual per-process reviewer evidence, approved operative rows, exact-SHA `release-write` grant and CURRENT deployment, relay/workflow contract checks, authorized runtime validation, and the required natural shadow/canary/output/consumer/alert/recovery proofs. The staged source release SHA is left null until the final integrated head exists. Expired guard grants are not restored or inferred here.

Legacy triggers stay authoritative until their lane reaches GO. A scoped cron grant comments only the exact approved matching line after fresh host fingerprint/equivalence checks. Protected lanes remain watch/escalation unless their existing policy and mechanical admission are met. Retired midday orchestrator slots are not restored. Independent broker, safety, recovery and host P1 scheduling remain in place.

Rollback stops candidate scheduling first, restores only the affected archived legacy trigger, verifies one scheduler and the original lock, and proves output recovery. It never restores an entire crontab or discards incident/receipt history.
