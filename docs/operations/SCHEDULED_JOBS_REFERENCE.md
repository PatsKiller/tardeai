## Trade AI User Timers — active vs retired

**Active** (`systemctl --user is-active` = active, enabled): `tradeai-continuous`, `tradeai-governance-pipeline`,
`tradeai-iris-taxonomy`, and the five `tradeai-portfolio-{backup,daily,weekly,monthly,lookthrough}-cadence`.

**Retired** (disabled + inactive — *intentional, not a fault*): `tradeai-governance-facts`,
`tradeai-governance-status`, `tradeai-maturity-board`, `tradeai-operator-readiness`. These four standalone
report timers were **consolidated into the single active `tradeai-governance-pipeline` controller** (Phase 200),
which runs them in order at the *preserved* cadence (Mon-Fri 07:40 / Sun 18:00):

```
a1a_docs_audit → system_facts → governance_status → maturity_control_board → operator_readiness → state_of_repo
```

The standalone timers are disabled so the work isn't double-run (and to avoid flock contention). Their outputs
(`docs/governance/governance_status_latest.*`, `docs/maturity_hardening/operator_readiness_latest.*`, …) are
regenerated by the pipeline each run — verify freshness there, not on the retired timers.

### "retired" annotation on System → Jobs (2026-07-07)

`/api/v2/system/scheduled-jobs` reports each user timer's `is-enabled` alongside `is-active` and derives
`retired = (enabled == "disabled" && status == "inactive")`. `SystemHub` renders those as an italic **`retired`**
pill (hollow marker) + tooltip instead of a bare gray `inactive`, so a deliberately-retired timer no longer reads
as an alarming fault. Purely systemd-state-driven — no hardcoded unit names; a normal enabled-between-runs timer
still shows `inactive`. `Failed: 0` on that page remains the real fault signal.

## Journal-learning thesis-review lane (2026-07-07)

`trade_thesis_review_engine.py` writes the **scored** post-trade reviews (`trade_thesis_reviews`, read by
`hermes_v_journal_learning_context` → the Hermes "journal learning" surface). It is distinct from
`post_trade_thesis_reviewer.py`, which writes the outcome-comparison table `trade_thesis_outcomes`.

The scored engine previously **had no scheduled runner** (invoked only via a Telegram command / a validation
script), so `trade_thesis_reviews` sat empty and Hermes flagged "journal learning empty". It also had two bugs
fixed the same day: `save()` defaulted to `dry_run=True` (so `--apply` silently wrote nothing), and the
`paper_trade_proposals` LEFT JOIN fanned one trade into N duplicate reviews (fixed with `DISTINCT ON (pt.id)`).

Now triggered three ways (all idempotent — `get_reviewable` skips trades that already have a review):
- **On trade close (primary):** `paper_trade_closer.py` post-close analytics + `paper_trade_monitor.py`
  auto-close path both fire `trade_thesis_review_engine.py --apply`.
- **Daily safety-net:** the 18:40 M-F cron above (`/tmp/thesis_review_engine.lock`).
