# Hermes Phase 29E — Morning Brief Storage Design

**Date:** 2026-06-01
**Status:** DESIGN ONLY — no DB changes

---

## Current State

Morning briefs are generated by `aegis_morning_brief_delivery.py` and stored as:
- Markdown files in `data/portfolios/reports/`
- Telegram messages (fire-and-forget, not stored)
- Dedupe file: `logs/.aegis_morning_brief_sent` (run_id only)

**No DB table exists for morning brief content.**

---

## Options

### Option 1: File-Only with Indexed Manifest

- Hermes Librarian scans `data/portfolios/reports/*.md` directly
- Create a manifest JSON listing brief files with dates and hashes
- No DB change needed
- **Pro:** Simplest, no migration
- **Con:** No structured query, no actionability scoring in DB

### Option 2: hermes_morning_brief_reviews table (NEW)

| Field | Type | Description |
|-------|------|-------------|
| id | BIGSERIAL | PK |
| brief_date | DATE | Brief generation date |
| file_path | TEXT | Path to source markdown file |
| source_hash | TEXT | SHA256 of brief content (dedup) |
| generated_at | TIMESTAMPTZ | When brief was generated |
| channel | TEXT | 'file' / 'telegram' |
| sanitized_summary | TEXT | Truncated, redacted summary (500 chars) |
| actionability_score | REAL | Per Phase 20C standard (0–1) |
| missing_fields_count | INTEGER | Count of missing actionability fields |
| backlog_required | BOOLEAN | Does this brief need a research backlog item? |
| reviewed_status | TEXT | pending / reviewed / archived |
| retention_until | DATE | Auto-purge date (90 days) |
| sensitive_flags_json | JSONB | What was redacted |

- **Pro:** Structured, queryable, integrates with Librarian
- **Con:** New migration, needs population script
- Requires separate approval to create

### Option 3: Extend communication_review_queue (Phase 20D design)

- Use the `hermes_advisory_message_reviews` table designed in Phase 20D
- Morning briefs are just another message_type
- **Pro:** Unified communication review
- **Con:** Table not yet created either

### Option 4: Use existing hermes_research_intelligence

- research_type = 'morning_brief_review'
- hermes_agent_name = 'hermes_librarian_agent'
- **Pro:** No new table, existing dashboard shows it
- **Con:** Mixes brief reviews with research findings, may distort table purpose

---

## Recommendation

**Option 2** (dedicated table) for production use, but **Option 1** (file manifest) as immediate low-cost step.

Immediate: Librarian can scan files in `data/portfolios/reports/` without any DB change.
Future: Create `hermes_morning_brief_reviews` table after separate approval.

---

## Privacy/Redaction

- Portfolio dollar values must be masked in sanitized_summary
- Account numbers excluded
- Broker references excluded
- Only aggregate observations retained

## Drive Sync Policy

- Morning brief reviews table data: NOT synced
- Design doc (this): synced

- Table creation requires separate Phase approval
- Population script requires separate Phase approval
- Librarian scan of files can proceed with existing file access
